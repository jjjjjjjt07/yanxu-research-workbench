## 可以直接使用的内容

- 本机地址：http://127.0.0.1:3000
- Windows启动入口：项目根目录的 `启动研序.cmd`。双击后在后台启动服务并打开浏览器；若服务已运行则直接复用。
- 前台运行方式：在项目目录执行 `npm.cmd run local`，保留该终端，按Ctrl+C停止。
- LearnBuddy需求与构建提示词：同目录 `LearnBuddy构建提示词.md`。先复制总提示词，再逐阶段构建和验收。
- 浏览器中的验证课题：`真实全文验证 · 图神经网络与分子预测`。包含三篇真实PDF、候选图谱、矩阵、保存的问答和一条待验证桥接假设。

本地服务不是互联网发布。只有本机能访问上述回环地址，关闭电脑后停止，重启后需重新双击启动入口。本地AI功能仍需网络及已配置的模型服务，免登录不等于离线模型。数据在 `.wrangler/state`，请保留该目录；`.env`为服务端配置，不要上传到源码仓库。

2. 手册第8.3节写有「禁止使用AI生成完整方案后直接提交」。分阶段提示词应配合本人学习、决策、实际修改和验收使用，不能把生成结果原样提交并声称完成了不存在的工作。
3. 第二部分及FAQ要求浏览器可在线体验的作品链接。localhost/127.0.0.1不能替代评委可访问的在线链接。原有Sites私有发布也不能直接当作已满足匿名访问要求；公开演示需独立验证访问权限、访客数据隔离、额度和后台执行器。
4. 手册列出的必需材料为作品链接、3分钟Demo视频、作品介绍PPT、GitHub/Gitee源码仓库、LearnBuddy使用记录。PPT含简介、赛题方向、AI能力、技术方案及团队信息。截止时间为9月26日23:59，截止前可修改提交，评委看最后一次。另有学术方向开源及第三方库说明要求；正式操作以平台和组委会最新通知为准。
5. 本项目最匹配「AI + 学术科研助手 / 文献知识图谱平台」。不应声称已经具备自动调研、算法生成、自动实验及论文评审的完整六环节科研流水线。

## 本次修复

第一，真实的1.6MB和2.2MB论文上传被框架的1MB multipart检查拦截，返回HTTP 413。已将框架入口的预算设为18MB，容纳应用已有的15MB文件上限和解析元数据；各业务端点仍保留自身限制。同样的两篇PDF重新通过浏览器上传成功。

第二，全文构图原先允许35实体及50关系，实测超过6500输出Token上限。现在要求每轮优先生成最多12实体、16关系和精简证据，并明确逐字保留换行、断词及块边界。末轮三篇均未因输出长度失败；两篇仍因部分引用不合法而部分完成。这是有限候选图谱，不是全文所有知识的完整抽取。

第三，新增显式本地免登录启动模式，仅Vite本地运行启用、只监听127.0.0.1，使用原有本地身份，因此已有课题不丢失。生产的所有权校验没有删除。本地入口还拒绝外部Host、非回环连接及跨站浏览器请求。

## 尚未达到的验收标准

严格摘录检查仍有一条空白差异。更重要的是，模型可能将「其他方法/基线」过度解释为「不是本文自己的实验」，而二次模型核查仍给出依据支持；这种语义强化不能靠引用存在性检查解决。问答有部分正确内容因为摘录不精确而降级为未知，双栏和公式解析仍影响可用证据覆盖。

正式学术验证仍缺：两个相邻领域合计20篇的固定论文集、独立研究者标注的实体/关系/证据金标准、未参与调试的保留集、真实实验复现数据，以及研究者效率对照。这些是原项目方案中的更高验收要求，不能用本次三篇论文替代，也不能把AI自己写的答案称为人工金标准。

本轮未重新覆盖全部历史接口测试、扫描OCR、每一种实验统计、附件和稿件交互。已有114项规则测试通过，但这些模块仍需针对正式演示场景选择端到端样例。论文中发表的实验结果没有被当成用户自己跑出的重复实验。

当前本地身份已到30个课题的原有限额，其中包括此前测试课题。未删除任何已有课题。继续创建新课题前需要另外安排可恢复归档或调整容量，不能直接清库。

## 交付和比赛发布的区别

本次按「本地网址、无需登录」完成本机交付，没有创建公网隧道、没有把个人研究资料公开，也没有代替用户提交赛事资料。若需评委从外部电脑体验，应发布一个使用公开样例的独立演示环境，验证无需平台账号，并配置访客隔离、调用预算及持续后台执行器。不要直接将现有本机数据库匿名暴露公网。

LearnBuddy提示词已包含这一公开演示阶段；用户可以在LearnBuddy实际构建后采用其支持的部署方式。现有代码是否直接作为参赛主体、开源许可选择、团队信息、视频及PPT仍由实际参赛材料决定。
