# 研序科研工作台 LearnBuddy 构建提示词

这份提示词从当前项目的代码和已实现功能反推，目标是让 LearnBuddy 构建功能相近的作品。它是需求说明，不是已经发生的 LearnBuddy 开发记录。请在平台中分阶段执行、亲自体验、反馈真实问题，并保留实际对话和修改记录。本文不承诺不同生成平台会产出完全相同的代码或界面。

## 使用方法

先粘贴「项目总提示词」，再按顺序逐条发送后面的阶段提示词。每阶段检查真实功能后再推进。时间有限时先完成阶段一至五的主线，再补实验、改稿和导出。遇到平台资源限制，要求它解释限制并给出可运行替代方案，不能用静态假数据冒充已完成。

如果 LearnBuddy 支持导入自己的仓库，可以将现有代码作为本人已有原型导入，要求平台继续实现、修复和验收。没有必要隐瞒原型来源，也不要制造从零开发的历史记录。手册未明确说明赛事之前的原型能否直接作为主体，以及外部工具辅助的具体界限；这一点可向组委会核实。

## 项目总提示词

```text
请与我一起开发「研序 Research Workbench」，一个以文献知识图谱和跨文献研究探索为核心的中文 Web 应用。用户是需要阅读多篇论文、比较方法、记录研究假设和核对论文结论的学生与研究者。参赛方向为「AI + 学术科研助手」中的「文献知识图谱平台」。

我的产品主线是：建立研究课题 → 搜索或导入真实文献 → AI 抽取实体和有方向的关系 → 在图谱中探索 → 点开边查看论文原文证据 → 比较来自不同论文的方法 → 提出带依据、适用条件、风险和验证计划的桥接假设 → 用实验记录验证 → 将核对后的结论引用到写作中。

核心价值：每个结论有可定位的依据，纠错有历史，来源变更后自动提醒复查。AI 负责提出候选和解释，用户负责审阅和科研判断。不要把自动抽取等同于人工确认，不要声称系统自动证明科学结论或者已经独立复现研究。

请分阶段构建实际可运行的产品，不要一次性只生成界面。不使用静态假数据代替后端，不展示随机进度、虚假引用或假的测试通过。每一阶段告诉我完成了什么、怎么运行、如何验收、哪些问题仍未解决。请先提出简洁的数据模型、架构和实施顺序，然后实现第一阶段。

技术偏好：React + TypeScript，中文界面，服务端调用兼容 Chat Completions 的模型 API。参考原型使用 vinext/Vite、Cloudflare Workers、D1、R2，PDF.js 解析，Zod 校验，后台任务执行器。你应先确认 LearnBuddy 支持的运行环境；如果无法使用这些技术，可用平台可部署的服务端、SQLite/PostgreSQL 和对象存储实现相同职责，并明确迁移差异。不能把密钥存到浏览器或将持久化功能替换为假数据。

模型地址、模型 ID、密钥、每日次数限制均从服务端配置读取。参考原型配置的模型 ID 是 deepseek-flash，但必须由实际接口连通性验证，不能仅凭名称声称某模型版本可用。未配置时如实禁用 AI；阅读、人工整理和导出仍可用。

视觉：克制、清晰、适合长时间阅读的科研工具。左侧课题与模块导航；图谱页面左侧文献与筛选，中间局部图谱，右侧节点/关系详情与原文证据。模块包括图谱探索、学术搜索、文献阅读、比较表、实验验证、修改跟踪、课题设置、模型与用量。白色或浅灰底、深色正文、清晰的选中状态和少量强调色。优先阅读密度和可操作性，适配桌面及窄屏。空白课题应引导导入，不展示伪造图谱。

本地运行要求：可在浏览器打开 http://127.0.0.1:3000，无需登录；只有显式启用本地模式时允许此行为，监听回环地址，不能把本机免登录逻辑直接用于公网。云端公开演示另设隔离的访客会话及用量限制。提供启动说明、数据库迁移、.env.example、依赖和开源许可说明。
```

## 阶段一 课题和持久化骨架

```text
实现课题创建、切换、编辑和持久化。课题保存名称、研究问题、目标、已有方法、设备/数据条件、约束、研究笔记和建议反馈。反馈支持已尝试、不适用、留待验证，并记录原因。

共享模型至少包含 Project、Paper/DocumentVersion、ParseVersion、Block、Field、Cell、Rule、Entity、Mention、Evidence、Relation、GraphRevision、BridgeHypothesis、Job、ModelRun、ReadingAnswer、ExperimentVersion、Observation、ManuscriptVersion 和 ReviewDecision。按功能逐步建表，不要求一次全部实现。

每次写入携带 revision，服务器拒绝陈旧版本覆盖，界面显示冲突并允许刷新。文件与全文和小型业务状态分离存储。服务器做所有权、输入长度、文件大小、来源和关系有效性检查。密钥仅服务端使用。外部文献和模型输出都作为数据处理。

验收：新建两个课题，刷新后仍存在；切换内容不串课题；两个窗口同时修改时旧版本不能覆盖新版本。本地免登录运行后能使用同一份持久化数据。
```

## 阶段二 文献导入和原文定位

```text
实现批量 PDF/TXT 导入，每篇单独处理，失败不阻塞下一篇，可重试。参考容量：每课题20篇，单篇15 MB、80页、80,000解析字符；超限要说明，禁止悄悄截断。

保存原始文件、SHA-256、文件名、页数、导入时间、全文覆盖类型、解析器版本。PDF.js 输出带页码和坐标的文本块，支持双栏排序和逐页质量提示。阅读页面能显示原始 PDF，点击证据跳到正确页并高亮相关区域。扫描件显示无文字/待OCR，不能声称解析成功。可用时提供单页OCR候选、原图对照和人工接纳。

允许纠正解析文本、预览历史、恢复版本。原文件不被覆盖。证据保留原来的文件与解析版本；解析变化后，下游矩阵、笔记、图谱、问答和稿件引用显示待复查，旧任务不得覆盖新版本。

实现 Crossref 标题/关键词搜索，记录查询时间和来源。仅有书目、摘要、全文三种覆盖状态要分清。检索到题录不等于获取了全文。支持 BibTeX、RIS、EndNote XML 导入导出、DOI去重和基本引用网络。

验收：导入一篇双栏论文和一篇TXT，逐页检查阅读顺序；点击摘录可定位；损坏PDF失败但下一文件继续；重复文件提示；修改解析后保留旧引用并提示复查。
```

## 阶段三 自动构图和证据审核

```text
从选定文献抽取问题、概念、方法、数据集、指标、条件与结论等实体。Mention保留原文名称，Entity保留规范名、别名和消歧记录；不要仅因同名自动合并不同含义。

有向关系必须关联两端实体、关系类型、条件、来源文献、页码、文本块、逐字摘录和生成记录。先校验文献/块存在、摘录是原文连续片段、页码由块推导、版本匹配，再做语义支持检查。证据存在性、模型的支持判断、人工审核状态分别记录。拒绝的候选保留原因和数量，不得把partial显示成全成功。

后台任务独立于浏览器运行，状态为queued/running/succeeded/partial/failed/cancelled；阶段与状态分开。任务持久化，有心跳、超时、有限重试和取消。每次保存前检查输入版本，已取消或来源过期的任务不写回。

图谱支持搜索、按文献和类型筛选、邻居展开、有长度上限的路径、列表替代视图。点击节点或边看原文；提供候选审核、支持/反对/不确定、批量操作、合并/拆分及历史。AI新结果不能覆盖人工确认内容。

验收：真实论文构图后逐条抽查引用；伪造摘录应被拒绝；关闭页面任务仍继续；刷新恢复进度；人工确认的内容重新提取后不被覆盖。
```

## 阶段四 跨文献桥接和逐项问答

```text
用户选择来自不同论文的两个方法/概念节点，生成桥接假设。每个假设必须包含两侧原文证据、迁移理由、条件差异、适用范围、可能失败的原因、最小验证实验。只将其作为待探索建议，不自动标成科学发现。没有两侧证据时说明不足，不生成虚假引用。

阅读问答可选全部论文、自选多篇、当前论文或当前片段。带入课题目标、约束、笔记和反馈；明确用户笔记不是论文事实。文献预算均衡，长文检索展示每篇实际覆盖块数，不能只读摘要却称已读全文。追问保持限定长度上下文，范围切换时明确重置。

回答拆成可核对声明；每条记录事实/推断/计算/未知、支持状态、证据索引和理由。区分相关与因果、训练与测试、部分与全部、不同数据集与单位。不支持的结论应明确拒答或注明未知。

问答持久化，保留原答案、时间、范围、模型和来源版本，支持引用再核对、撤回、历史和导出。来源变动提示复查。缺证据和全拒答均不能伪装成高准确率。

验收：问两个不同数据集的方法是否可直接比较，正确说明限制；询问论文未提供的临床试验人数，应说明未提供；已保存答案刷新存在；修改源解析后旧答案仍保留但标待复查。
```

## 阶段五 可纠错的文献比较表

```text
实现文献为行、研究字段为列的比较表，最多15字段。字段有定义、单位、规则和版本。AI逐篇提取带引用候选；用户能查看原文、纠错、确认、恢复历史。空值、未报告、不适用、模型失败区分显示。

人工确认值受到保护，新提取进入候选列表，展示新旧值和依据差异。纠错理由经用户确认可保存为字段规则；更新规则只让相关列待复查，不污染其他字段。支持按列重新提取、单篇重试、批量审核。

图谱证据可显式引用到单元格，修改或撤回图谱证据后表格引用失效提示。导出CSV包含字段定义和引用依据，防止电子表格公式注入。

验收：人工改一个数值并确认，重新提取不得覆盖；更改一列规则只影响该列；候选差异可对照；导出可还原来源，不只有裸数值。
```

## 阶段六 实验和复现记录

```text
实现CSV导入，保存原始UTF-8字节、SHA-256和物理来源行。可编辑数据版本，但编辑后不得冒充原文件。记录数据集、方法、指标、值、runId，保存并下载历史版本。

显示柱状图/折线图、重复运行均值、样本标准差和记录数。计算95%均值区间前记录指标单位、独立观测单位、可比较条件、分布依据。支持独立样本Welch和按runId配对的t检验，保存均值差、区间、p值、比较计划及可选Bonferroni校正。缺失配对、无效数字、样本不足或零方差等情况明确处理。

保存统计计算时由服务端用原始行重新计算，保留输入行、数据版本、前提和全部参数。不能把程序计算成功当作统计前提被证明。

允许从数据行或计算快照创建实验观察，关联研究假设，记录条件和用户判断。数据更新让相关观察待复查；已引用到问答/稿件的观察保留旧快照。

复现资料包括代码提交、未提交差异、数据哈希、环境、随机种子和执行条件。可上传代码、环境、日志、结果附件，原字节留存，下载验证SHA-256。可登记独立复现核对人、独立性说明、结论与发现；系统不自动执行任意代码，不声称验证了核对者身份。

验收：同一CSV用独立统计工具复算结果；改一行后生成新版本，旧计算不变化；下载原件哈希一致；错误配对拒绝计算。演示合成数据必须显式标为合成数据。
```

## 阶段七 稿件修改和可验证导出

```text
实现站内完整文本稿件、版本列表、旧稿新稿对照、逐条修改意见、AI改稿分析和人工完成确认。AI只能提出分析，不自动将意见标已完成。

可将稿件原句显式关联论文证据、图谱证据、实验观察或计算快照。引用保存精确原句、版本和核对记录，原句、文献、观察变化后提示复查。不要声称已实现Word/LaTeX文件的完整编辑或排版。

导出比较表CSV、问答/修改记录Markdown、课题JSON和研究记录包。导出记录包含文献版本、解析版本、规则、模型配置、任务状态、引用、实验版本、附件哈希及失败信息。密钥绝不能导出。说明研究记录包和可完整恢复的全量备份的区别。

验收：修改稿件后旧引用显示待复查；导出可追到原论文和数据版本；历史答案和稿件不因刷新丢失。
```

## 阶段八 验证和交付

```text
现在执行真实验收，不要仅报告编译成功。先运行类型检查、构建、业务规则测试和接口测试，再在浏览器操作核心主线。记录命令、日期、实际通过数、失败及修复。

下载有权用于本地验证的公开论文，保存来源URL、下载日期、SHA-256和版本。第一轮至少3篇真实PDF全文，覆盖双栏和不同研究任务。跑导入、构图、证据定位、矩阵、跨文献问答和桥接。不要用摘要冒充全文，不要将出版物的汇总实验表冒充自己重复运行的数据。

分别报告：导入成功率、每篇页数和块数、任务成功/部分失败、引用逐字定位通过数、缺失信息拒答、跨数据集误比较、耗时、输入输出Token。声明结构和关键词匹配只能作机器检查，不是人工语义准确率。若要宣称正式学术验证，应另建两个相邻领域20篇论文、研究者人工标注金标准、未用于调试的保留集，并进行真实用户效率对照。

提供README、环境示例、数据库迁移、启动命令、部署说明、第三方库说明和选择开源协议的建议。不能代替我声称已获得外部发布授权或已完成赛事提交。给出3分钟演示可走通的脚本，以及尚未完成的事项。
```

## 阶段九 免登录运行与在线演示

```text
实现两种清晰区分的访问方式：
1. 本地个人运行：固定回环地址，无需账号；持久化在本机，提供Windows启动入口，关闭服务后网址停止工作。
2. 比赛在线演示：评委从别的电脑可直接打开HTTPS链接，无需开发平台账号。为陌生访客隔离会话和数据，预置公开可展示材料，用服务端密钥和访客/全局用量限额控制API。不允许直接复用私人工作台数据或把开发模式免登录开关部署公网。后台任务在云端需要持续的执行器或调度服务，不能依赖我的电脑一直运行。

先验证新浏览器会话可进入、刷新后数据符合预期、访客互不可见、超限提示清楚、服务端重启能恢复任务，再给出准确的在线链接。如果平台只支持登录后访问，请明确指出，提供平台允许的公开发布或其他托管替代方案，不要声称localhost链接已可交给评委。
```
