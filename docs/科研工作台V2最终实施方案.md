# 研序 V2：以文献知识图谱与跨学科探索为核心的科研平台

日期：2026-09-07。文档性质：最终实施方案与验收约定，不表示功能已实现或已上线。

2026-09-12 执行约束更新：按用户最新要求，最终模型使用 **DeepSeek V4.1 Flash**（`deepseek-flash`）；**不需要私有化发布**，本轮以现有软件的本地改进、运行与验证为交付。后文共享/部署条款只在以后明确要求发布时适用。实际已完成范围与未完成事项见 [V2 实施与验收记录](V2实施与验收记录.md)，不把本方案的全部目标当作已经实现。

## 1. 产品决定

保留现有工作台，采用渐进改造。根据用户最新决定，核心定位调整为：支持实体关系自动抽取、交互式图谱可视化与跨学科桥接发现的文献知识图谱平台。证据链是图谱可信的基础，可复现性使抽取和发现过程可检查。

主线为：提出研究问题 → 搜索或导入文献 → 自动抽取实体与关系 → 图谱探索与证据核对 → 发现跨文献或跨学科连接 → 保存可验证的研究假设。阅读、比较、实验和修改跟踪服务这条主线。

首页为图谱探索工作区：左侧文献与筛选，中间局部图谱，右侧节点、关系与原文证据。首次无文献时提供搜索或导入入口；不展示虚构的已生成图谱。默认围绕一个问题展示有限节点，支持搜索、逐层展开与列表替代视图。系统综述、重复实验统计和团队权限按项目需要启用。

核心功能为自动构图、交互探索和跨学科桥接。学术导航是图谱的数据入口，课题阅读是证据解释器，矩阵是选中节点的结构化对照视图，实验是桥接假设的验证记录，改稿是经核对结论的输出与检查工具。已有辅助能力保留；扩展它们不能阻塞图谱第一版。本文其他章节的完整能力仍保留为目标，优先级以本节和第 10 节为准。

## 2. 当前基础与证据边界

本次核对源码确认：React/TypeScript 前端，Cloudflare Workers 服务端，D1 与 R2；项目状态主要为带 revision 的 JSON 快照。已有引用摘录位置校验、人工确认保护、候选值、逐篇任务、课题条件和阅读反馈、实验版本及数值关系检查、稿件意见清单。

当前限制包括：问答内容与来源没有逐句绑定；PDF 解析按文本位置分组，缺乏双栏、表格和公式的结构化处理；稿件历史截断为最近 10 次；模型记录主要覆盖名称、用量、耗时和状态；任务执行仍受页面请求驱动。

前次执行的 16 项规则测试和 26 项本地接口检查通过。它们验证软件机制，不代表真实论文正确率、用户效率或全部云端操作通过。用户提供的进度冲突、导出反馈及基线版本问题纳入回归用例；每项修复仍需在对应界面复现和验收。浏览器控制超时独立记录，不与网站 AI 超时或解析失败混为一谈。

## 3. 总体技术架构

采用模块化单体作为核心业务服务，逐步替换大 JSON 状态，避免一次性重写。重计算解析和长任务通过独立执行器处理。首阶段保留 D1、R2、现有身份与前端组件；若托管环境不支持所需后台队列或解析运行时，接入独立服务，不在浏览器里模拟后台执行。

核心数据流：搜索/文件 → 文献版本 → 结构解析 → 原文实体提及与证据 → 实体消歧 → 关系候选与支持检查 → 版本化图谱 → 局部探索与路径查询 → 桥接候选 → 验证记录。矩阵、问答和稿件引用共享的实体、证据和声明。

增加 Entity、Mention、RelationAssertion、GraphRevision 和 BridgeHypothesis 实体。名称相同不等于实体相同；Mention 保留原文表述和坐标，Entity 管理规范名称、别名与消歧决定。每个关系声明保存两端实体、关系类型、方向、条件、证据与审核记录；多篇论文对同一关系的支持或反对分别保留。图谱版本保存数据版本及抽取配置，布局只是可复用的视图配置。

先通过关系存储层实现局部邻居、条件过滤和有长度上限的路径查询。是否引入专用图数据库根据真实规模、查询延迟和运维条件决定；图谱产品不必以数据库重构作为首个交付物。

任务、身份权限、版本、审计横贯所有层。业务模块只能通过统一业务服务更新共享对象，不能各自复制并修改一份证据。

### 核心实体

| 实体 | 核心内容 | 关键规则 |
|---|---|---|
| Project / ProjectRevision | 研究问题、条件、约束、阶段、成员 | 反馈和建议绑定条件版本 |
| Work | DOI 等标识、题目、作者、出处、年份、类型 | 代表学术作品，区别于某个 PDF 文件 |
| DocumentVersion | Work、原文件哈希、获取来源、导入时间、发表状态、版本关系 | 预印本与正式版关联，不静默合并 |
| ParseArtifact / Region | 解析器版本、页、章节、段落、表格、公式、图注、坐标、质量提示 | 重新解析创建新产物，旧引用仍可定位 |
| Evidence | 文献版本、解析版本、原文摘录、区域列表、章节/表图号、上下文 | 稳定 ID；一条证据可包含多个不连续区域 |
| FieldDefinitionRevision | 字段定义、单位、口径、适用研究类型、提取规则 | 修改后传播待复查标记 |
| Observation | 原值、规范值、单位、统计类型、样本量、实验条件、证据 ID | 零值与未知分开；计算值有公式与输入引用 |
| Candidate / ReviewDecision | 新旧候选、审核状态、审核人、原因、时间 | 人工确认值不被 AI 覆盖 |
| Claim / ClaimEvidence | 原文事实、计算结果、综合推断、未知；支持/反对/限制关系 | 一个句子有多个主张时拆分验证 |
| AnalysisRun | 模型、参数、提示词版本、完整检索清单、输入输出、时间、校验结果 | 不保存密钥；保存可重放输入与实际输出 |
| ScreeningDecision | 标准版本、阶段、审核人、决定、排除理由 | 双人决定在揭盲前相互不可见 |
| ExperimentRun / DatasetVersion | 原始数据、行标识、代码、环境、种子、硬件、超参数、重复编号 | 派生数据和图表可回溯输入及计算 |
| ManuscriptVersion / CommentResolution | 稿件基线、后续版本、稳定段落 ID、意见与证据 | 恢复历史产生新版本，旧版不覆盖 |
| Job / JobItem / Attempt | 批次、逐篇阶段、计数、重试、错误、租约 | 后端为进度唯一事实来源 |
| AuditEvent / ExportManifest | 操作者、对象版本、前后引用、关联运行、导出清单与哈希 | 与业务变更可靠关联，导出可验证 |

共享证据不意味着把所有对象塞进一张表。原文证据、提取观察、结论、用户偏好和审核决定必须分别建模。

## 4. P0：可信基础与立即可见的修复

### 4.1 逐项证据支持检查

先运行确定性校验：文献与版本存在、摘录真实、坐标有效、数字和单位可关联、计算可重算、条件可比较、确认值未被覆盖。

再运行有范围的语义检查：拆分主张，检查是否强化因果、必要性、普遍性、比较范围和统计结论。输出“支持、部分支持、冲突、无法判断”，并指出对应主张、证据和原因。不得用模型自报百分比伪装成校准概率。

例：“实验使用 GPU”只支持实验配置事实，不能推出“必须使用 GPU”。“在数据集 X 上更高”不能推出“全部数据集更好”。

语义检查仍可能出错，第二个模型同意不是事实证明。高影响结论及不确定结果必须保留人工审核状态。程序检查失败的候选不进入已确认矩阵；事实存在性和结论支持性分别展示。

问答提供两种模式：

- 原文摘录：只返回可定位的原文与出处；翻译若启用，单独标明为翻译。
- 证据分析：逐句区分原文事实、计算结果、综合推断和未知；依据不足时显示“无法判断”，允许另列待验证建议。

不能仅以未检索到片段断言“论文未报告”。显示已检索章节、覆盖范围与解析缺口，区分“未找到”“未报告待核对”“不适用”“解析失败”。

### 4.2 后端任务状态机

状态与阶段分开：状态为 queued/running/succeeded/partial/failed/cancelled；阶段为 parsing/retrieving/extracting/validating/persisting。可跳过已完成的解析阶段。取消、超时重试、人工重试均有明确迁移规则。

批次分别显示“已结束 3/3、成功 2、失败 1”，不能把已结束比例当成功率。未知耗时阶段只显示阶段或不确定进度，不伪造平滑百分比。只有结果提交成功才增加完成计数。

每篇保存完成字段数、总字段数、失败类别、尝试次数、心跳和最后更新时间。执行器需支持幂等、租约、退避重试、重复消息去重、过期结果检查与失败恢复；关闭浏览器不终止已提交任务。写入旧规则或旧文献版本的结果必须被隔离。

### 4.3 导出与基线

导出中心显示文件名、生成时间、范围、格式、大小、校验值与可重新下载入口。状态区分生成中、已生成、已发起下载和失败。普通浏览器不能确认任意本机保存路径或实际落盘，因此不显示虚构路径或未经证实的“保存成功”；使用系统保存接口时按实际能力显示位置。

首次保存稿件创建 v1 并显示在全部版本列表，下一次修改创建 v2。无变化保存不制造空版本。已有旧稿可导入为明确标记的基线，不伪造过去的创建时间或作者。

### 4.4 候选与筛选反馈

显示逐字差异，同时区分纯格式变化、单位等价、数值变化和条件变化。接受、保留、合并均产生审核决定。批量核对先展示范围和差异摘要；语义有变化、来源变化或存在警告的记录不得默认批量接受。

搜索显示“筛选结果 1/3 篇”；批量动作清楚区分当前筛选结果与整个项目，保留跨页选择提示。

## 5. 文献管理、搜索与系统综述

### 文献管理与学术导航

DOI 精确匹配优先，题目与作者近似匹配作为候选。补全元数据时记录提供方、获取时间和字段来源；冲突保留供选择。文件哈希识别完全重复文件；作品去重与版本识别分开，不能仅凭题目相似自动合并预印本和正式版。

支持 BibTeX、RIS、EndNote XML 导入导出；Zotero 首先做标准格式与标识符互通，再实现授权库读取与明确范围的增量同步。不得把支持 EndNote XML 宣称为支持所有 EndNote 私有库格式；双向同步需处理冲突、删除和附件权限。

搜索从研究问题生成可编辑关键词与检索式，接入真实学术数据源。结果显示题目、作者、年份、来源、DOI、文献类型、检索来源、摘要/全文可用性及推荐理由；记录检索日期和返回集合。引用次数不能直接当证据质量分数。

入库后复用现有解析、阅读、矩阵和图谱。只拿到摘要时不得声称已读全文。中文问题与英文论文检索需做查询扩展并保存实际使用的检索式。

候选数据源：OpenAlex 用于发现与引用关联，Crossref 用于 DOI 元数据与发表后更新。实际接入前验证权限、费用、限流和学科覆盖，并提供降级及失败提示。

### 系统综述工作流

保存研究方案、纳入排除标准版本；支持标题摘要初筛、全文复筛、排除理由、待处理与全文未获取等状态。流程统计由唯一记录和决策事件计算，区分检索记录、文献报告与研究，避免多个报告对应同一研究时重复计数。

双人独立筛选、盲态保存、分歧裁决、审核人签名。报告一致率和适用的一致性指标，说明缺失值、分类分布和样本范围。AI 可提供建议，不能冒充第二名独立研究者。

PRISMA 统计与流程图是报告辅助，不宣称自动满足完整报告规范；实现时对照适用版本的官方清单。

## 6. PDF 与结构化提取

采用有质量检查的分级解析：文字页布局识别 → 双栏阅读顺序 → 表格/公式/图注区域 → 扫描区域 OCR → 质量报告与人工纠正。

解析任务在独立执行器运行。保留原 PDF、解析 JSON、解析器版本、语言、耗时、每页质量与失败原因。OCR 或复杂解析若需外部服务，明确上传范围与数据处理方式；优先评估可自行部署的方案。

表格保留表头层级、行列及跨页关系、合并单元格、单位、脚注、均值/标准差/区间和对应坐标。不能可靠还原的内容作为待复查结构，禁止无提示变成整齐但错误的数值表。

来源点击定位 PDF 原始区域，多块证据可逐一切换。保留页面图像辅助核对。检索清单显示章节、页码、实际块数及解析失败页；字符数覆盖不等于语义理解充分。

数值模型同时保留原文字符串、规范数值、单位、统计量类型、数据集、样本量口径、实验组/对照组、条件、证据和来源类型。单位换算生成派生观察，不覆盖原值；不根据摘要或设备型号补造数值。

## 7. 核心产品：文献知识图谱与跨学科桥接

图谱是共享证据和结论的视图，不另存一套无法追溯的 AI 摘要。节点包括问题、概念、假设、公式、方法、数据、观察与结论；边包括依赖、使用、支持、反对、限制、对比与待验证关联。

自动抽取先生成可探索的候选图谱，机器提取与人工核对状态明显区分，用户无需先逐条审核才能开始探索。每条边显示来源、适用条件、生成记录及审核状态；经过审核的内容进入已核对视图。未知关系不自动补齐。

构图处理包括：识别文献类型与章节 → 抽取问题/概念/方法/假设/数据/结论的原文提及 → 归并缩写、同义词和跨语言别名 → 抽取有方向及条件的关系 → 确定性与语义检查 → 保存候选图谱及覆盖清单。实体合并支持预览、人工拆分与可追溯恢复，避免错误合并污染全部关系。

分别显示文献引用网络、概念方法网络、结论证据网络。引用关系不能标作结论支持；语义相似不能标作因果或方法适用。三种视图可以切换和交叉定位，但不把所有类型默认堆在同一张图上。

区分三种阅读用途：概念学习路径、方法及假设对照、结论与证据网络。默认只展示当前问题和一层邻居，支持逐步展开、过滤、搜索以及等价的列表视图，避免无法阅读的大图。

核心交互：搜索节点，按类型/年份/来源/核对状态过滤，展开邻居，固定布局，查看关系依据，选择两个方法比较，查询有证据的连接路径，查看相互冲突的声明，保存探索视图和研究假设。点击证据直接定位 PDF 区域；侧栏宽度可调整，窄屏分视图切换。节点颜色之外还用文字和图形标识类型，保证键盘与列表访问。

跨学科桥接明确标为假设：给出两侧来源、概念映射、条件差异、潜在失败原因及最小验证实验，不把相似度当作方法可迁移的证明。

桥接分为已知连接与候选迁移。先按共同研究问题、数学结构、方法作用或约束相似性召回，再检查两侧证据和适用条件，排除仅名称相似的连接。桥接卡包含问题、来源 A、来源 B、映射关系、证据路径、条件差异、反例/风险和验证步骤。用户可标记值得探索、已尝试、不适用及原因，反馈绑定具体课题条件。

首版桥接控制在两个相邻学科的文献集合，先证明能识别有意义与无意义的连接。不得承诺自动发现科研创新，也不能把“当前文献库未出现”写成“学界无人研究”。

证据被纠正或版本失效时，相关图谱边、问答、矩阵与稿件标记待复查，已发表或导出的旧结果仍保留其原版本。

## 8. 实验、证据质量与稿件

实验记录代码提交号及未提交差异、代码/数据哈希、随机种子、环境锁文件或镜像标识、硬件、超参数、数据划分、预处理和执行时间。记录缺失项，不把空白标记为可复现。

原始 CSV 保留文件与行标识；转换生成新数据集版本，图表携带数据选择、变换、单位和样式配置。每个数值可回溯到原始行与计算过程。

支持重复实验、均值/标准差/置信区间与误差条。统计检验先确认独立/配对结构、样本单位、分布和多重比较方案；返回效应量、方法假设与计算记录，禁止对任意数字自动生成显著性结论。统计功效只能在信息和假设充分时计算。

结论模型支持指定数据集、多个数据集、全部指定集合、数值差异、相对提升和统计判断。集合范围明确保存；新数据加入集合或关系改变都触发复查。

证据质量按研究类型使用可解释的检查清单；机器学习、工程测量和临床研究不共享一个简单证据等级。区分已知问题、信息缺失和需要专家判断，不自动给所有论文一个“可信分”。

稿件模块使用稳定段落 ID 与意见对应关系，基于实际差异生成回复草稿。实验相关意见可链接实验与证据记录；只增加一句声称已完成实验的文字不算落实。作者最终确认。

## 9. 版本、审计、团队与可复查导出

应用版本采用追加记录，恢复产生新版本。审核及高价值历史不得静默截断。保存事务或可靠 outbox 同时记录业务变更与审计事件；大附件用哈希引用。逻辑上的不可变历史不等于防篡改存储，需区分应用权限、备份及未来可选的签名校验。

权限在服务端执行：项目角色、对象/字段操作范围、核对分配、审核签名。双人提取盲态、揭盲差异与裁决记录共用审核模型。导出、搜索、图谱与后台任务同样遵守授权范围。

一键导出研究记录包：允许导出的文献文件、元数据、证据、字段和候选、审核记录、提示词模板与模型调用清单、检索范围、原始/派生数据、代码环境记录、图表配置、稿件版本、筛选流程、审计记录、manifest 与文件哈希。密钥和无关私密信息不进入导出。

模型调用可复查包括实际输入与输出；模型服务端变化可能导致重放输出不同，不能承诺逐字重现 AI 回答。确定性计算则应在锁定环境中复算一致。上传论文的再分发与外部模型发送范围依用户权限处理。

## 10. 迁移与实施阶段

| 阶段 | 实现内容 | 阶段出口 |
|---|---|---|
| A 第一条可用图谱闭环 | 复用上传与原文定位，加入最小 Evidence/Entity/Mention/Relation/Run/Job/Audit 模型，完成自动构图、局部探索、关系证据侧栏与图谱导出；统一相关进度反馈 | 从真实论文生成图谱，能沿一条跨论文关系逐项核对出处；支持拒绝或纠正候选 |
| B 构图可靠性与迁移 | 实体消歧、版本关系、逐句/关系支持检查、解析质量报告、候选批量审核、完整版本迁移与任务恢复 | 合并错误可恢复，跨模块证据共用，失败与旧任务结果不会污染图谱 |
| C 搜索与跨学科桥接 | 接入学术搜索、元数据、BibTeX/RIS、两个相邻领域的候选召回、证据路径、适用性检查与桥接卡 | 搜索到的文献能入图，每个桥接建议可检查两侧来源并记录验证决定 |
| D 研究闭环辅助 | 图谱选中对象转阅读对照/矩阵，反馈持续使用，实验记录与稿件结论关联；补齐剩余现有 P0/P1 | 图谱发现能进入验证，纠正证据或更新数据能提示受影响对象 |
| E 文献与协作扩展 | Zotero、EndNote XML、系统综述、双人盲态审核、细粒度权限、重复实验统计与完整审计包 | 扩展能力接入同一图谱与证据体系，通过角色、恢复和记录包检查 |

身份、项目隔离、基础审计与版本绑定自 A 阶段强制执行；E 阶段增加完整协作能力。A 阶段交付完整的小范围图谱流程，不先花多个阶段做完所有辅助模块。已有数据保护问题随相关改动及时修复；原稿、实验、文献管理现有能力持续保留。

迁移先备份并验证可恢复性，再建立新表及兼容读取。旧块、单元格、候选与历史转换成明确带 legacy 标记的记录，缺失时间、模型及身份写“未知”。迁移幂等并核对数量、哈希和引用完整性。按项目切换唯一写入路径，避免长期双写分叉；保留原始快照用于回滚和检查。

继续使用现有模型完成基准；模型替换经同一组固定样本比较准确性、拒答、延迟与成本决定，不以模型名称作为验收。

## 11. 必须通过的验收

### 确定性与数据保护

- 已确认值不被重新提取覆盖；接受、保留、合并和批量操作都可追溯。
- 规则/文献更新期间到达的旧任务结果不会混入新批次。
- 3 篇中 1 篇失败时显示 2 成功、1 失败；刷新、关闭页面和重复执行不改变计数真实性。
- 零、未知、不适用和错误状态分别导出；原始单位与换算过程保留。
- 首次稿件保存有 v1；恢复历史有新版本；不伪造旧审计记录。
- 源证据、实验行或条件变化时，依赖对象准确标记待复查。
- 导出生成失败与下载触发失败可见；记录包哈希、引用和版本完整。
- 项目和字段权限由服务端验证，包括后台任务、图谱和导出。

### 学术可靠性基准

初始采用两个相邻领域合计 20 篇有权处理的真实论文，人工标注核心实体、别名、关系类型、方向、证据及适用条件。包含名称相同含义不同、术语不同含义相近、真正冲突与条件差异、合理桥接及明显不适用的反例。增加双栏、扫描、跨页表格、公式、脚注和不同版本样本。建立人工核对答案与保留集，不能只用开发时看过的论文验收。

核心指标分别报告实体识别、消歧错误、关系正确性、证据定位和支持充分性；图谱节点数和边数不是质量指标。桥接评价由研究者核对相关性、两侧依据、条件映射、可验证性与重复建议率，报告 top-k 候选质量及覆盖，不宣称客观测得科研创新性。交互验收覆盖查找关系、解释路径、比较方法、纠正实体、保存假设和更新后复查。

逐句检查用例覆盖：使用/必须、相关/因果、部分/全部、训练/测试样本、不同单位、不同数据集、统计显著性、缺失材料、矛盾来源、检索遗漏。分别报告支持判断准确性、危险误判数量、拒答率与覆盖率；不能通过全拒答取得表面正确率。

解析报告文本顺序、表头与数值归属、单位脚注关联、坐标定位和失败检测；不只统计识别出多少字符。预设严重数值错配和无依据强结论为阻止发布的问题。所有百分比报告样本数，不能将小样本通过称为普遍保证。

### 真实效率与交付

在相同材料与统一答案标准下比较普通文献阅读与图谱辅助流程：定位某个方法的前置假设、找到跨论文共同点与冲突、解释一条连接并回到原文、形成可验证假设所需时间、错误和遗漏。比较表效率作为辅助指标。使用交叉顺序或等价材料减少熟悉效应。由真实研究者参与审核金标准，不能把 AI 自评作为唯一证据。

每阶段交付运行代码、迁移与回退说明、变更记录、真实操作截图、验证结果与未覆盖范围。共享或公开部署按实际访问范围执行所需发布确认，不改变站点权限来方便测试。

## 12. 执行与能力边界

由 Codex 实施代码、迁移、接口接入、自动化验证、浏览器测试和文档。用户只需在确需本人操作时提供登录、外部服务授权及费用决策，并参与研究标准和真实使用反馈。

工程复杂度可以通过分阶段实现承担；OCR 歧义、缺失原文、版权、统计假设和模型不确定性需要产品显式处理。软件帮助研究者查证和复现，不自动证明论文结论正确，也不以“已核对”代替同行评审。

- [Crossref 元数据与发表后更新接口](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)
